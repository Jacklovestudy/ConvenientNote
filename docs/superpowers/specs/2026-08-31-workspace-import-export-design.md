# Convenient Note 笔记导入导出设计

## 目标

为“笔记”模块提供一次性打包与迁移功能。导出结果是单个 `.cnote` 文件；导入会覆盖当前未删除的笔记，并在当前进程内刷新笔记页面，不重启应用。

## 数据边界

导出只包含同时满足以下条件的记录：

- `BoardKey == TodoBoardKeys.Notes`
- `IsDeleted == false`

每条导出笔记保留 ID、标题、纯文本、富文本 JSON、位置、尺寸、颜色、层级、完成状态、笔记本 ID、标签、置顶、收藏和创建/更新时间。只打包这些笔记引用的本地图片。

以下数据不导出，也不因普通导入而删除或改写：

- Day Todo、待办箱、日程、已达成等非笔记记录。
- 回收站中 `IsDeleted == true` 的笔记及其媒体。
- 工作区名称和工作区创建/更新时间。

导入时先删除当前所有未删除笔记及其媒体，再写入备份中的未删除笔记。当前回收站始终保持不变，不实现笔记 ID 冲突处理；若数据库拒绝写入，则整个导入事务失败并恢复原活动笔记与媒体。

不包含单篇选择、合并、去重选择、Word/PDF/Markdown、自动用户备份、云同步或崩溃恢复向导。

## 文件格式

`.cnote` 是专用扩展名的 ZIP：

```text
ConvenientNote-笔记-2026-09-01.cnote
├─ manifest.json
├─ notes.json
└─ media/
   └─ <note-id>/
      └─ <image-file>
```

`manifest.json`：

```json
{
  "format": "convenient-note-notes-backup",
  "schemaVersion": 1,
  "appVersion": "1.0.0",
  "exportedAtUtc": "2026-09-01T06:00:00Z"
}
```

`notes.json` 使用独立 DTO，仅包含未删除笔记集合，不直接序列化 EF Core 实体。导入层拒绝空 ID、重复 ID、缺失字段、非法领域值和 `IsDeleted == true` 的记录。媒体路径继续按笔记 ID 分组，因此富文本图片引用无需改变。

## 用户界面

移除左侧导航抽屉底部的工作区“导出数据 / 导入数据”。在笔记墙顶部工具栏加入一个紧凑的“导入/导出”菜单，位于“新建笔记”旁，菜单项为：

- `导出笔记`
- `导入笔记`

单菜单设计避免最小窗口宽度下新增两个按钮挤压搜索和筛选控件，并保持操作只出现在其所属模块。

导入选择文件并完成校验后，只显示一次确认：

> 导入将覆盖当前未删除的全部笔记和图片，待办与回收站不受影响。此操作无法撤销。

按钮为 `取消` 和 `覆盖并导入`，取消是安全默认项。弹窗和成功提示中的数量只统计包内未删除笔记，例如 `共 5 条笔记`。

## 导出流程

1. 若编辑器打开，停止延迟保存并等待正在进行的保存完成，再保存最新内容；保存失败则中止导出。
2. 读取当前工作区，筛选未删除笔记。
3. 写入 manifest、`notes.json` 和这些笔记的媒体目录。
4. 先写同目录临时文件，关闭 ZIP 后覆盖移动为目标 `.cnote`。
5. 显示 `导出完成，共导出 N 条笔记`。

## 导入流程

1. 将用户选择的包复制到应用控制的临时快照，预览和最终导入只使用同一快照。
2. 校验 ZIP 路径、manifest、schema、`notes.json` 和媒体归属；所有校验完成前不修改当前数据。
3. 用户确认后，停止笔记页面的新保存并等待已开始的保存和媒体清理完成。
4. 在临时目录准备导入媒体。
5. 将当前未删除笔记的媒体目录移动到临时回滚位置；回收站和非笔记数据的媒体目录保持原位。
6. 在单个 SQLite 事务中删除当前未删除笔记并写入导入笔记。回收站和其他记录不变；任何主键冲突都使事务整体回滚。
7. 数据库失败时恢复原活动笔记媒体；成功后删除临时回滚目录。
8. 移除缓存的旧 `NotesView`，重新创建笔记页面并显示导入内容。窗口标题和其他导航页面无需重载。
9. 显示 `导入完成，共恢复 N 条笔记`。

## 组件边界

### 笔记备份服务

负责创建、检查和导入笔记包，只接收筛选后的活动笔记。包内计数等于活动笔记数。

### 仓储笔记替换接口

新增事务化的活动笔记替换操作。SQLite 和 JSON 仓储都只替换 `BoardKey == Notes && !IsDeleted` 的记录；不得删除回收站或其他板块记录。任何 ID 冲突按普通导入失败处理。

### `NotesView`

负责菜单、文件对话框、覆盖确认、保存排空、成功/失败提示和导入后的笔记页刷新。`MainWindow` 只保留通用导航和关闭协调，不再拥有导入导出入口。

## 错误处理

- 非笔记备份包、版本过高、JSON 无效、包含已删除记录或 ZIP 越界路径：拒绝导入。
- 校验失败不修改数据库或媒体。
- 数据库或媒体替换失败：恢复当前活动笔记和媒体。
- 导出失败：删除临时文件。
- 导入/导出期间阻止重入和关闭窗口。
- 临时快照清理为 best-effort，不遮蔽主要成功、取消或错误结果。

不实现合并、逐条跳过或复杂恢复流程。

## 测试

- 工作区同时包含 5 条活动笔记和大量待办时，预览与结果均显示 5。
- 导出包只含活动笔记；回收站和待办不在 `notes.json` 或媒体中。
- 导入后活动笔记被替换，待办、日程、已达成和回收站记录完全不变。
- 导入发生 ID 冲突时事务回滚，回收站和当前活动笔记保持原样。
- 富文本字号、颜色、行距、列表、标签、分类、状态和图片保持一致。
- 导入包缺少的旧活动笔记及其媒体被删除。
- 损坏 JSON、高版本、删除状态记录和路径攻击不会修改现有数据。
- 数据库失败时原活动笔记、回收站、待办和媒体均保持。
- 待保存内容会在导出前写入；导入后旧保存不会写回。
- 导入后只重建笔记页面，不重启应用。

## 验收标准

- 功能入口只出现在笔记页面。
- 导出的 `.cnote` 只携带未删除笔记和对应图片。
- 导入只覆盖未删除笔记；非笔记数据和回收站不受影响。
- 用户看到的数量与笔记墙活动笔记数量一致。
- 导入完成后笔记页面立即显示新内容。
- 无效或失败导入不会留下半写入数据或缺失图片引用。
